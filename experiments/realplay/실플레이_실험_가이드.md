| 실험자가 학습 데이터 녹화자인지 기록 안 됨 | 시작 화면에 체크 칸이 생겼습니다 |

## 2. 질문에 대한 답

**발까지 다 나와야 하나요?** 네, 본 실험은 발까지 나오게 하세요.
- 모델 입력에는 발목과 발 관절도 들어갑니다(33개 관절 전부).
- 학습 데이터는 학교에서 발까지 보이게 찍었습니다. 발이 잘리면 MediaPipe가 화면 밖 발 위치를 추측하고, 그 좌표는 학습 때와 달라집니다.
- 그래서 **기본 조건은 학교처럼 넓은 공간(3~4 m, 발까지 보임)**에서 합니다.
- 발이 잘리는 조건은 "좁은 공간"으로 따로 한 번 해서 비교합니다. 1회차가 사실상 이 조건이었습니다.

**30 FPS로 고정이 안 되는 게 원래 그런가요? 웹 브라우저 때문인가요?**
- 게임 코드는 프레임률을 고정하지 않습니다. 웹캠은 1초에 30장을 보내지만, 한 장을 처리하는 데 33 ms보다 오래 걸리면 다음 장을 놓칩니다.
- 1회차 기록으로 보면 이렇습니다.
  - 사람이 없을 때는 29.3 FPS였습니다.
  - 사람이 잡히면 포즈 추정, 미리보기 그리기, 분류가 더해져 26.6 FPS(프레임 간격 평균 37.6 ms)로 떨어졌습니다.
  - 프레임 간격이 40 ms를 넘는 경우는 7%였습니다.
- 웹 브라우저(특히 영상 재생 중인 탭), 녹화 프로그램, 백신 검사는 CPU를 같이 쓰므로 **끄는 게 좋습니다**. 노트북이면 전원을 꽂고 Windows 전원 모드를 "최고 성능"으로 하세요.
- 논문에 주는 의미: 논문의 ms 값은 30 FPS(33.3 ms)로 환산했습니다. 이 PC의 실제 루프는 1프레임에 약 37.6 ms라서 실제 시간은 약 13% 더 깁니다. 실플레이 결과는 실제 시각으로 재므로 이 차이가 이미 반영됩니다.

## 3. 실험 계획 (1시간 이내, 자세한 이유는 `실험계획_토론_1시간안.md`)

시작 화면 위쪽의 **회차 설정 버튼**을 누르면 블록, 반복 횟수, 촬영 조건이 자동으로 맞춰집니다.

| 순서 | 버튼 | 내용 | 시간 |
|---|---|---|---|
| 1 | ① 본 실험 | 발까지 보임, 조명 켬. 연습, 대기 4종, 지시 동작 ×2, 빠른 잽, 비스듬히 서기 | 약 17분 |
| 2 | ② 조명 끔 | 자연광 또는 어두운 상태. 준비 자세 대기 2종, 지시 동작, 빠른 잽 | 약 7분 |
| 3 | ③ 좁은 공간 | 약 1 m 다가가 발이 잘리게. 준비 자세 대기 2종, 지시 동작 | 약 6분 |
| 4 | ④ 다른 사람(선택) | 학습 데이터 녹화에 참여하지 않은 사람 | 약 8분 |

준비와 쉬는 시간을 합쳐 **40~50분**입니다. 빠진 것은 기본 조건 반복, 좌우 연타, 역광·멀리, 휴대폰 지연 측정입니다(이유는 토론 문서).

## 4. 준비 (매 회차)

1. 게임, 웹 브라우저, 녹화 프로그램을 끄세요.
2. 카메라에서 3~4 m 떨어져 **머리부터 발까지** 미리보기 창에 들어오는지 확인하세요(기본 조건).
3. 시작 화면 위쪽에서 **회차 설정 버튼**을 누른 뒤, 아래를 확인하거나 고치세요.
   - 이름 이니셜(예: P1)
   - 촬영 조건
   - 메모(예: "학교 ○○실, 3.5 m, 형광등")
   - 학습 데이터 녹화 참여 여부
   - 반복 횟수
4. **[실험 시작]**을 누르세요.

## 5. 실행 중 조작

| 키 | 기능 |
|---|---|

## 5-1. 중간에 문제가 생겼을 때 (화면 꺼짐, 자리 비움 등)

1. **Esc로 멈추세요.** 그때까지의 기록은 저장되고 분석도 자동으로 됩니다. 분석 중에는 창을 닫지 마세요(진행 막대가 보입니다).
2. **`시행_편집.bat`**: 가장 최근 회차의 시행 목록이 열립니다.
   - 사람이 화면에 없던 시행은 **빨강(자동 제외)**으로 이미 빠져 있습니다.
   - 잘못 입력됐다고 생각하는 시행을 클릭(Ctrl·Shift로 여러 개)하고 **[선택한 시행 제외/해제] → [저장 후 다시 분석]**을 누르세요.
   - 기록 자체는 지워지지 않고, 분석에서만 빠집니다. 다시 누르면 되돌릴 수 있습니다.
3. **`실플레이_실험_시작.bat` → [중단된 회차 이어하기]**: 빠진 시행과 남은 블록만 자동으로 계산됩니다. 설정을 확인하고 [실험 시작]을 누르세요.
   - 새 폴더에 저장되고, 회차 합치기에서 앞 회차와 함께 합쳐집니다.

이번 판부터는 **실험 중 화면 꺼짐과 절전이 자동으로 막힙니다.**

## 7. 결과 보기

- 회차마다 `results\<날짜_시각_이니셜>\결과요약.md`가 생깁니다. 기록 점검, 모델별 표, 쉬는 구간 오발동, 표시한 시행 수가 들어 있습니다.
- 여러 회차를 합치려면 **`회차_합쳐서_분석.bat`**을 실행하세요. `results\종합_결과.md`에 촬영 조건별, 그리고 전체 합계가 나옵니다. 1회차(예비 실험)는 자동으로 빠집니다.
- 다른 모델로 다시 보려면 `결과_다시_분석_전체모델.bat`(가장 최근 회차)을 쓰세요.
- **회차를 마칠 때마다 폴더 이름만 저(Claude)에게 알려 주세요.** 기록을 함께 확인하겠습니다.

## 8. "게임까지 넣은 end-to-end가 필요한가?"

- **모델 비교에는 필요 없습니다.** 이 도구가 게임과 같은 인식 코드를 그대로 돌리기 때문입니다.
- 1회차에서 새로 알게 된 점: **실제 게임 파이프라인은 같은 프레임을 재생한 시뮬레이션보다 입력이 중앙값 150 ms 늦었습니다.** 분류를 별도 스레드에서 돌리고 쿨다운 같은 규칙이 더해지기 때문으로 보입니다.
- 화면까지의 끝단 지연은 계산으로 나오지 않습니다. 재고 싶으면 선택 블록 "화면 반응 지연"을 휴대폰 슬로모션(240fps)으로 찍으세요. 영상에서 팔이 움직이기 시작한 프레임부터 화면이 깜빡인 프레임까지 세면 됩니다.

## 9. 결과를 논문에 쓸 때

- **같은 사람(참가자 1, 학습 데이터 녹화자)의 결과**는 새 사용자 성능이 아닙니다. 이 사실을 함께 적습니다.
- 지시를 보고 하는 동작이라 실제 게임보다 규칙적일 수 있습니다.
- 재생 평가는 쿨다운과 게이팅을 뺀 시뮬레이션입니다. 실제 게임 값은 "게임 파이프라인" 줄입니다.
- X로 표시한 시행은 뺀 값이 기본이고, 뺀 개수가 결과요약에 나옵니다.

## 11. 시험한 내용

- 가짜 입력 자동 시험: 연습, 대기, 지시 동작, 좌우 연타 블록. 연습 블록은 분석에서 빠졌고, 표시한 시행은 지표에서 빠지는 것을 확인했습니다.
- 회차 합치기: 1회차로 확인했습니다.
- X 키, P 키, 예시 사진 표시는 자동 시험으로는 누를 수 없어서, 코드 경로만 확인했습니다. 첫 회차에서 한 번 눌러 보시고 화면 아래에 "표시했습니다"가 나오는지 봐 주세요.
