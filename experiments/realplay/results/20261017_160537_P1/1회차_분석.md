## 2. 관찰하신 점 확인

### (1) "오른발 앞 + 주먹 살짝 들면 오른손 펀치가 나간다" → **맞습니다**

- **손을 내린 대기 블록에서는 오발동이 없었습니다.** 가만히 60초, 움직이며 45초 모두 모든 모델에서 0건이었습니다.
- **손을 든 준비 자세(쉬는 구간)에서 나왔습니다.** 실제 게임 입력은 쉬는 구간 229초 동안 오발동 6건이었고, **6건 모두 오른손 펀치**였습니다(왼손 0건). 6건 중 3건은 왼손 지시 뒤, 3건은 오른손 펀치 지시 뒤의 복귀 중에 나왔습니다.
- 좌우 치우침은 **배포 모델에서 특히 컸습니다.** 쉬는 구간 오발동은 다음과 같습니다.

| 모델 | 쉬는 구간 오발동 | 오른손 | 왼손 |
|---|---|---|---|
| 배포 모델 | 13건 | 11건 | 2건 |
| GAP 4프레임 (5시드 평균) | 8.2건 | 4.8건 | 3.4건 |
| LSTM 3프레임 (5시드 평균) | 27.6건 | 12.2건 | 15.4건 |

- **추정 원인(측정한 것 아님).** 배포 모델은 증강이 실제 거울상이 아닌 방식(x 부호만 반전)으로 학습되었습니다(논문 4.3절). 같은 구조를 제대로 좌우 반전해 학습한 GAP 4프레임에서는 치우침이 작았습니다.
- **발 위치까지는 좌표로 확정하지 못했습니다.** 정면 카메라에서 앞뒤 발 구분은 깊이 추정에 의존하기 때문입니다.

### (2) "어퍼컷 때 펀치가 먼저 나간다" → **맞습니다. 모델마다 차이가 큽니다**

어퍼컷 지시 34회 중 같은 손 펀치가 먼저 나간 비율입니다.

| 경로 | 비율 |
|---|---|
| 실제 게임 입력 | 29% (오른손 어퍼컷은 17회 중 7회) |
| 배포 모델 재생 | 29% |
| **GAP 4프레임 (5시드)** | **10%** |
| MLP 1프레임 | 27% |
| LSTM 4프레임 | 44% |
| **LSTM 3프레임** | **62%** |
| LSTM 2프레임 | 71% |

- 실제 게임에서 오른손 어퍼컷 미발동 7회는 대부분 펀치가 먼저 나가서 어퍼컷이 막힌 경우로 보입니다.

### (3) 확정 프레임 (코드 확인: `tools/udp_send_webcam_ml.py`)

- **Precise에서는 펀치와 어퍼컷 모두 2프레임**입니다(스쿼트 3프레임). 펀치만 늘린 것은 아닙니다. 1프레임 확정은 Rapid와 Max Speed입니다.
- 어퍼컷과 펀치를 구분하는 장치는 따로 있습니다.
  - **어퍼컷 뒤 펀치 보류.** 어퍼컷이 예측되거나 전송되면 이후 4프레임 동안 직선 펀치를 막습니다(`PUNCH_HOLDOFF_AFTER_UPPER_FRAMES = 4`). 다만 이건 어퍼컷이 **먼저** 잡힌 경우에만 작동하고, 팔이 올라가는 도중 펀치로 먼저 잡히는 경우는 막지 못합니다.
  - **어퍼 윈드업 억제.** 손목이 어깨보다 아래면 직선 펀치를 보류하는 옵션입니다(`--upper-windup-punch-suppress`). 코드에는 있지만 **게임은 이 옵션을 켜지 않습니다.**

| 중간 자세에서 다른 공격 먼저 (4.13) | GAP4 13.6% 대 LSTM3 18.4% (교차검증 합성) | 어퍼컷 때 펀치 먼저 GAP4 10% 대 LSTM3 62% | **같은 방향이고 차이는 훨씬 큼** |

**실제 게임이 재생보다 150 ms 늦은 이유(코드로 본 추정).**

- 그 위에 쿨다운, 재무장, 가드 처리 같은 규칙이 더해집니다.
- 정확한 분해는 하지 않았습니다.

## 4. 이번 결과가 논문에 주는 의미

1. **GAP 4프레임 선택의 근거가 실데이터로 강해졌습니다.** 실제 동작에서 LSTM 3프레임은 어퍼컷을 펀치로 먼저 내보내는 오류가 많았습니다. 짧은 펀치에서는 놓침 차이가 없었습니다.
2. **반응 속도는 예측대로 LSTM이 약 1프레임 빠릅니다.**
3. **실제 게임의 지연은 시뮬레이션보다 깁니다.** 논문의 "약 100~140 ms"는 시뮬레이션 값이라고 이미 밝혀 두었습니다. 실제 파이프라인은 더 늦다는 점을 한 문장 추가할 가치가 있습니다.
4. **배포 모델의 좌우 치우침과 어퍼컷 혼동은 게임 개선 과제입니다.** 논문에서는 한계로 적을 수 있습니다.

## 6. 추가 정보를 반영한 해석 (10/17 저녁)

- **실험자: 참가자 1.** 학습 데이터를 녹화한 3명 중 한 명입니다. 손을 내린 대기에서 오발동이 0건인 것, 교차검증 예측(1분당 약 6.7건)보다 오발동이 적은 것은 이 때문일 수 있습니다. 새 사용자 성능으로 쓰면 안 됩니다.
- **장소: 집.** 학습 데이터와 시연은 학교의 넓은 공간에서 했습니다(3~4 m 이상, 발까지 전신). 이번에는 약 1 m 좁아서 발이 잘리는 경우가 있었고, 조명도 달랐습니다. 모델 입력에는 발목·발 관절도 들어가므로, 발이 잘리면 MediaPipe가 추정한 발 좌표가 학습 때와 달라집니다. **오른손 펀치 오발동의 일부는 이 조건 차이 때문일 수 있어 원인을 하나로 단정하지 않습니다.** 다음 실험에서 "기본(발까지 보임)"과 "좁은 공간(발 잘림)"을 나눠 확인합니다.
- **지시와 다르게 한 시행(본인 보고).** 좌우 연타를 4번씩 친 시행, 처음 대기를 좌우 번갈아 한 것, 펀치를 어퍼컷과 헷갈려 애매하게 높게 친 시행이 있었습니다. 어느 시행인지 기록되지 않아 개별로 뺄 수 없습니다.
  - 좌우 연타 지표("양손 모두 발동")와 대기 블록 결과는 영향이 작습니다.
  - "펀치→어퍼컷"류 오분류 몇 건은 실제로 높게 친 펀치일 수 있습니다.
- **처리 방침.** 1회차는 **예비 실험**으로 두고, 회차를 합친 종합 결과에서는 뺍니다(`meta.json`에 `use_in_aggregate: false`). 다음 회차부터는 X 키로 해당 시행을 바로 표시할 수 있습니다.
- **그래도 유지되는 결론.** 어퍼컷 때 펀치가 먼저 나가는 비율의 모델 간 차이(GAP4 10% 대 LSTM3 62%)는 너무 커서, 몇 건의 애매한 시행으로 뒤집히지 않습니다.
